## 配置与沿用内容

- 模型：现有配置的 `deepseek-v4-flash`，DeepSeek Anthropic 兼容接口；
  默认温度、未设随机种子，模型别名不代表不可变权重版本。
- 两个合成 Python 任务，每题两个冻结依赖子任务；不是 SWE-bench 数据。
- B 明确使用完整历史；C 使用生产 scoped resume，16,000 估算 token 上限。
- 只提供四个文件工具；任务、权限、验收与预算在 B/C 间一致。
- 沿用 2026-10-04 run02 中真实 `os._exit(73)` 后的 F3 快照；本轮没有重新
  执行前半段。B/C 从相同数据库字节和源码哈希恢复，且使用原绝对路径。
  duration 顺序 B/C，inventory 顺序 C/B。
- 每条完整轨迹最多 32 次模型调用、150,000 累计 token 停止阈值；单响应
  可越过 token 阈值。每阶段最多 600 秒，SDK 不自动重试。实际用量远低于限制。
- 输入计数为 provider 的 `input_tokens + cache_read_input_tokens +
  cache_creation_input_tokens`。B 恢复后未缓存输入=2,961、缓存读取=8,704；
  C 分别为 4,330、11,776。没有使用价格表，不声称节省人民币/美元费用。
- 共享前缀分别计入假想完整轨迹后，B 两题总输入=20,115、总输出=3,493；
  C 总输入=24,556、总输出=4,000。前缀真实只执行一次，不能重复计作实际支出。
- 恢复耗时从恢复进程内 Runtime 开始计时，不含历史租约等待和进程启动。
  恢复后 token 包含剩余编码工作，不等于纯恢复开销。

## 修复与验证

根因：`_pending_calls` 对文本完成回复返回 `[]`，恢复循环却用
`pending_calls is not None` 判定是否回放。已提交的完成标记处理后，空列表
仍被追加为 `{"role":"user","content":[]}`。真实 API 拒绝该消息，
ScriptedModel 却接受，故既有测试未暴露问题。

修复将空工具批次规范化为 None；非最终已验证标记之后，持久化一条指向
下一子任务的 user 提示，使用已有 `input_ready` 阶段。相同处理用于
正常继续和 F3 恢复，不绕过 verifier，不编辑数据库跳过租约。

两项最小回归测试修复前稳定失败，修复后通过，并验证末条消息为合法
user 提示、下一子任务只消耗一次模型调用预算。另有真实进程退出与快照
复用测试。共 **151 项相关测试通过**：已有恢复/计划 46 项、已验证子任务/
DAG/证据/重规划 101 项、新增回归与 pilot 4 项。实际模型四条续跑也
确认没有空消息并通过最终验收。

run01 的提示协议错误（完成标记混入工具回复）和 run02 的四次 API 400
均保留。它们是单独的调试记录，不与本轮成功率混合，也没有被覆盖。

## 结论与范围

本轮验证了实验流程和修复后的 F3 恢复可用性，没有证明 scoped resume
在长任务上更省钱，也没有证明总体完成率非劣。样本只有两题，每分支
一次；没有本轮无中断对照。任务很短，历史本来就不大。

最终检查在新进程独立调用，但复用子任务断言，并非额外隐藏覆盖。
文件内容未变不等于所有副作用恰好执行一次。下一步适合冻结更长历史的
任务并重复配对续跑，检验首次输入缩减能否转化为稳定的总成本收益；本轮
不据此扩展 planner 或修改 scoped 策略。
