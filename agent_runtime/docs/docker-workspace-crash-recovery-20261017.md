# 冻结容器进程崩溃恢复实验

日期：2026-10-17。结论：**本轮离线准入检查通过，仍需独立审查；未执行真实 Agent 或 SWE-bench 评测。**

本轮只增加上轮尚未覆盖的控制器进程崩溃场景。没有重跑上轮已通过的 12 项后端测试、5 个容器场景、镜像构建、API Smoke 或历史 Harness。所有实现位于 `codex/completion-recovery-contract` 实验工作树，未提交或推送。

## 实现变化

- 新增 `docker_recovery.py`：将冻结快照及恢复日志通过临时文件、文件 fsync、原子替换及 POSIX 目录 fsync 持久化。记录完整容器身份、Docker Engine ID、实例与验证规则、任务/仓库租约身份、控制器 PID/启动时间/boot ID、快照哈希及字节数、已停止进程身份。
- `DockerWorkspaceBackend` 默认仍拒绝接管已暂停容器。只有可信控制器显式配置恢复日志和 Runtime 租约身份回调，才启用接管；不接受模型给出的所有者字符串作为授权。
- 恢复要求：同一任务与仓库、新 owner、更大的 fencing token、旧进程已退出、同一 Docker/source/规则绑定、源容器仍暂停、完整且未损坏的快照。导出未完成、源已恢复运行、旧进程仍存活、租约失效或身份不匹配时拒绝。
- 新所有者先持久化接管身份，再清理遗留验证容器及继续验证。验证容器增加完整 source-ID 标签；清理必须同时匹配 session、source、image，不使用全局清理。
- 新增 `Runtime.verification_lease_identity()` / `EventStore.current_lease_identity()`，读取前续租并核对当前绑定的租约。原有 Verifier、SQLite 权威提交事务、任务完成契约仍是唯一成功判定入口。
- 释放前日志进入 `releasing`，成功解除暂停及按 PID/start-time 恢复原写入进程后记为 `released`。此间崩溃目前要求人工处置，不宣称可自动恢复。

## 新增测试结果

**15 项新增离线回归通过**。覆盖正常接管持久化、重复接管拒绝、旧 fence/同 owner/错误任务或仓库、旧进程存活、源已运行、不完整/已释放日志、身份不匹配、快照损坏或超限、接管期间丢租、原子替换失败及无有效 Runtime 租约。进程存活等规则在单元测试中注入；以下容器实验使用真实子进程退出。

真实实验采用原有本地固定镜像与 WSL Docker，不拉取或重建镜像。每个场景创建独立小型仓库与隔离容器。候选修改由控制器写入，ScriptedModel 仅返回固定响应；不是 Agent 自主修复。

子进程在目标窗口执行 `os._exit(73)`，不运行 Python 清理。监督者等待原租约自然到期，随后由新 Runtime 接管，未通过改写租约表模拟进程死亡。

| 崩溃窗口 | 崩溃后权威/语义检查点 | 恢复结果 |
|---|---|---|
| 导出开始 | 0 / 0 | 拒绝不完整导出；不生成成功记录 |
| 导出已落盘、尚未暂停 | 0 / 0 | 源仍运行，拒绝接管旧快照 |
| 源已暂停 | 0 / 0 | 同源新租约恢复，重新验证成功；原后台写入进程随后恢复 |
| 验证容器启动 | 0 / 0 | 清理遗留验证容器，再验证并提交 |
| F2 提交前 | 0 / 0 | 新租约恢复并重新验证；最终仅一个成功检查点 |
| F2 事务中 | 0 / 0 | SQLite 回滚，无半提交；恢复后仅一个成功检查点 |
| F3 提交后 | 1 / 1 | 核对冻结证据并复用已提交权威结果；恢复验证执行次数为 0 |

**7 个新增真实进程/容器场景均符合预期：5 个恢复成功，2 个拒绝自动恢复。** 五个正向场景均由 fence 1 的旧所有者转交 fence 2 的新所有者；恢复模型调用均为 0。恢复后的存储不变量检查通过。

两个拒绝场景中的“隔离”表示停止自动处理并报告需人工处置，不是新增数据库隔离状态，也没有将任务错误标记完成。测试拥有者核对后销毁其源容器。最终对本轮归属标签的检查应见证据中的清理清单。

## 风险与下一步边界

- 这是 Linux、同一 Docker daemon、可信控制器与独占 Docker 管理端点下的崩溃恢复协议。日志不是防管理员篡改的签名证据；Docker API 与 SQLite 之间不存在跨系统原子 CAS，不能宣称可对抗任意特权操作。
- 未完成导出、导出后尚未暂停、释放中崩溃仍须人工核对或销毁源容器；可能有停止的写入进程，不会猜测性地恢复它们。没有引入自动无限重试。
- 未覆盖主机断电、daemon 重启/永久挂起、所有网络故障、解除暂停或 SIGCONT 失败的完整矩阵。进程退出与 fsync 实验不等于断电耐久性认证。
- 本轮验证规则是固定的小型命令探针；未验证长时官方评测、真实模型定位与写入能力，亦未完成 Shell 读取错误的可信结构化桥。
