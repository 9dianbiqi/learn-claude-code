## 复现与修复

首先用两个最小测试注入 unpause/thaw 异常，**修改前均失败**：验证与语义检查点已经提交，数据库任务为 `completed`，但 Runtime 通用异常分支向调用方返回 `failed`；释放失败还跳过了 `freeze-release` 记录。红灯日志与 JUnit 保留在证据包，未删除。

修复后：

- `WorkspaceCleanupError` 单独携带清理报告；Runtime 记录 `workspace_cleanup_requires_review` 事件并向调用方抛出异常，不把清理故障转换为任务验证失败。已提交的验证结果和语义检查点保持一致。调用方不会收到一个正常的成功返回值。
- 若验证或租约本来已经失败，释放错误不覆盖原始异常；另存释放报告，并在支持时附加异常说明。
- 释放报告分别记录阶段、API 是否确认解除暂停（`unpaused`）、独立查询的实际暂停状态（`observed_paused`）、是否完成恢复进程（`processes_resumed`）和人工处置要求。API 超时不能推断操作未生效。
- 心跳续租持续至释放结束；解除暂停后再次核对所有权，若心跳失效就不再发送 SIGCONT。未引入自动释放重试。
- 释放关键阶段持久化到原有日志；只有全部成功才进入 `released`。`releasing` 日志继续拒绝自动接管。进程直接退出时不会伪造 finally 清理记录。

成功权威仍来自原有 Verifier 与 SQLite 事务。没有新增另一套任务成功状态机，也没有改动 PlanRevision、权限或预算规则。

## 新增测试结果

**8 项新增离线回归通过**：两类提交后释放失败、unpause 已生效但响应丢失、原始异常保留、解除暂停后丢租不发送 SIGCONT、缓慢释放期间继续心跳、SIGCONT 后确认失败，以及拒绝接管 releasing 日志。

**6 个新增真实容器场景符合预期**。使用原有 WSL Docker 与固定本地镜像；小型候选仓库由控制器写入，ScriptedModel 返回固定文本。后台写入进程在验证前被停止。

| 场景 | 故障方式与观察 | 判定 |
|---|---|---|
| unpause 被拒绝 | SDK 边界注入 APIError，未调用 daemon unpause；源仍暂停 | 独立清理异常，需人工处置 |
| unpause 响应丢失 | 先执行真实 daemon unpause，再注入 ReadTimeout；源已运行，写入进程仍停止 | 记录实际状态，未盲目重试 |
| 恢复进程命令失败 | 将容器内恢复程序替换为固定非零退出程序，实际调用原 `_thaw` 检测失败；源运行、写入进程仍停止 | 独立清理异常，需人工处置 |
| unpause 前崩溃 | 子进程 `os._exit(73)`；源仍暂停，日志 releasing | 无 finally 记录，拒绝接管 |
| unpause 后崩溃 | 子进程直接退出；源运行、写入进程仍停止 | 拒绝接管，未自动发送 SIGCONT |
| SIGCONT 后崩溃 | 子进程直接退出；源运行、后台写入恢复，但释放确认未完成 | 日志仍 releasing，拒绝猜测完成 |

三个 API/命令故障是**确定性故障注入**，不是本轮观察到的真实 daemon 故障或网络丢包。第三项没有单独保存该 exec 的 inspect 返回值；保留了固定替换程序、实际错误分支和进程状态，不把注入配置冒充独立退出码采集证据。三个进程退出则是真实子进程死亡，不执行 Python 清理。

六项均在验证提交后发生：数据库任务保持 `completed`，权威检查点与语义检查点各为 1；存储不变量和 SQLite 完整性检查通过。此处 completed 仅表示该离线候选通过其固定验证，不表示容器清理完成。

六项均由持有新租约的 Runtime 携带原恢复日志尝试 resume；均因 releasing 状态拒绝自动接管，模型调用 0，没有返回缓存完成结果或重复验证。监督者随后按本轮归属移除容器，未使用全局清理。最终容器清单见归档。
