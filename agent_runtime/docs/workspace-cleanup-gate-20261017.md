# 清理待办跨入口阻塞与人工协调实验

日期：2026-10-17。结论：**本轮离线检查通过，仍待独立审查；未提供 Agent 修复能力或 SWE-bench 成功证据。**

本轮验证上轮留下的“忽略清理错误，另建后端绕过”的入口。只增加对应回归与两条容器集成路径，未重跑旧轮测试矩阵、构建镜像、调用模型 API 或执行官方 Harness。修改保留在 `codex/completion-recovery-contract` 实验工作树，未提交或推送。

## 先复现，再复用现有机制

最初两个测试均红：释放失败后，另建后端的 resume 仍可返回缓存完成；同仓库新普通任务仍可调用模型。旧机制只保留了清理异常、文件日志和审计事件，未登记仓库副作用阻塞。

现有 `operations` 和工具人工协调入口要求真实工具调用，不能用来伪造一个模型工具调用。现有 `effect_reservations` 支持独立预留，因此本轮复用这张表、仓库租约、fencing、`EffectBlocked` 和已有状态：

`running → completed`（释放确认）或 `running → unknown → completed`（失败/崩溃后人工核对）。

没有新增清理状态表、任务完成状态或 Schema 版本；任务的验证成功仍只来自既有 Verifier 和权威事务。

## 最小实现

- `workspace_cleanup.py` 使用控制器线程的 ContextVar，把 Runtime 完成验证作用域与后端释放连接起来；模型工具接口不包含这些函数。
- Docker 后端在**开始释放前**预留 `workspace_cleanup` 副作用，绑定完整 source ID、镜像、session、Docker Engine ID。正常释放关闭预留；失败保留 unknown；直接进程死亡留下 running，现有租约接管将其转为 unknown。
- 修改已有租约接管/释放逻辑，只对该资源类型保留原绑定信息，避免 unknown 转换覆盖 source 身份。其他副作用的原有逻辑保持原样。
- Runtime 的统一 `_acquire` 入口检查同仓库的清理预留，覆盖新任务、恢复和缓存完成入口，不依赖调用方继续传入旧日志。阻塞发生在模型调用及后端快照读取之前。
- `Runtime.resolve_workspace_cleanup` 是可信控制器/操作人员接口，模型不可调用。操作人员先自行处置容器，再由只读观察器核对**同一 Docker 引擎、同一完整 source ID 的 404**，在新租约下通过 CAS 关闭 unknown 预留。容器仍存在、daemon 不可达、证据不匹配、租约过期或重复处理均不解除。
- 复用的投影不变量原先假定所有预留都有工具调用且不能挂在终态任务上。本轮仅对绑定有效的资源预留添加明确适配；普通工具预留的规则保持严格，v4 迁移预校验默认不接受此例外。没有伪造工具调用记录。
- 新阻塞入口还暴露了一个上下文问题：取租约失败后 `_active_task_id` 仍被改成未进入的任务。将激活上下文移到成功取得租约之后，新用例先红后绿。

释放之外的早期冻结崩溃仍使用上轮显式恢复协议；本轮不会在导出/验证之前就预留释放副作用。释放一旦开始并登记预留，崩溃后采取人工核对策略，不自动猜测释放是否完成。

## 新增验证结果

**18 项不同的新增离线测试通过，分 15 项与新增 3 项两批执行。** 覆盖两种绕过入口、正常释放、仓库隔离、人工确认后继续执行、容器存在、错 source/engine、缺少观察方法、空理由、重复确认、确认期间租约过期、daemon 不可达、有效 404、阻塞后的上下文、不变量例外边界及旧投影校验保持严格。

初始绕过测试的两次失败、开发中发现投影规则不适配的失败，以及上下文测试的一次失败均归档；没有把这些开发失败隐藏为从未发生。

两条真实进程/容器路径复用了前轮已经建立的故障注入方式，但验证的是**新增的跨入口阻塞与人工协调闭环**，不是声称发现两种新的 Docker 故障。

| 新集成路径 | 观察 |
|---|---|
| 忽略释放异常 | 注入 thaw 非零退出；副作用为 unknown；另建后端、不传旧日志仍被阻塞；新普通任务也被阻塞 |
| 释放中控制器死亡 | unpause 后真实 `os._exit(73)`；副作用先为 running；等旧租约自然到期，新持有者接管为 unknown；完整资源身份保留；两个入口均被阻塞 |

两条路径继续完成以下闭环：

1. 被阻塞阶段模型调用 **0**、capture **0**，未返回缓存完成结果。
2. 原容器仍存在时，操作人员只读核对失败，预留不变。
3. 实验拥有者显式删除该容器，再由持有新租约的操作人员核对真实 Docker 404；关闭对应预留。
4. 同仓库新的普通离线任务可继续执行（每条路径一次 ScriptedModel 调用，非真实模型 API）。
5. 原任务仍为 completed，成功检查点仅一个；全库不变量检查通过。这里 completed 仅表示历史离线候选验证结果，不代表 Agent 修复成功。

容器实验运行后新增的上下文修正只调整激活变量顺序，使用最后三个新增测试验证；没有为了该修正重跑两条容器实验。归档保留 `runtime-at-container-run.py` 和最终源码，可核对这一区别。前 15 项测试也未为了归档重复执行。
